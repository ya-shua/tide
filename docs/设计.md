# 汐（Tide）· 插件设计文档

> 一句话：**汐不是聊天机器人，是给她装的一套"活着"的状态系统。**
> 情绪会衰减，肚子会饿，你太久不理她会委屈，但你只是话题聊完了，她不记仇。

- 插件名：**汐**（英文代号 Tide，只指这个模块，不是角色名）
- 角色名：**不硬编码**，由 `config/角色.yaml` 的 `name` 决定，默认填角色名占位符
- 形态：独立 Python 包，零外部强依赖；可被 QQ 桥接、微光小屋壁纸、微光域沙箱共同调用
- 许可：自写部分 MIT；**不复制** AGPL 项目代码（Shikigami 只借思路）

---

## 1. 定位与边界

### 它负责什么

1. **听懂对方情绪**：语音声学 + 文本语义双通道，融合成一个"对方情绪状态"。
2. **拥有自己的情绪**：持续存在、会衰减、会被事件改写的内部状态。
3. **有生理与依恋需求**：饿、困、无聊、想你。不是装饰，会影响回复。
4. **判断该不该有反应**：能分清"你不理我"和"这话题已经聊完了"。
5. **决定怎么说话**：把情绪翻译成 TTS 的情感参数、回复长度与语气。

### 它不负责什么

- 不做 ASR、不做 TTS 合成本身（调外部引擎）
- 不做长期记忆存储（记忆在桥接层，Tide 只消费"最近发生了什么"）
- 不做人格设定（人格在 `角色.yaml`，汐只读取）
- 不做对话生成（LLM 负责；Tide 输出"该怎么回"的约束）

## 2. 需求清单（验收标准）

| # | 需求 | 验收标准 |
|---|---|---|
| R1 | 语音情绪识别 | 收到一段语音，能输出对方情绪标签 + 强度，而不只是转写文本 |
| R2 | 文本情绪识别 | 纯文字消息也能判定情绪，覆盖 8 类以上 |
| R3 | 自身情绪 | 情绪有类型、有强度、随时间衰减；同样的调侃，心情好和心情差回应不同 |
| R4 | 情感语音 | 同一音色，情绪不同时语速/音高/情感 instruct 不同 |
| R5 | 小脾气 | 被凶、被冷落后产生委屈值；委屈未消时回复更短更冷；安抚后恢复 |
| R6 | 思念 | 长时间无互动，思念值上升，达到阈值会主动发消息 |
| R7 | 饥饿 | 饥饿值随时间上升，影响精力与耐心；"吃饭"类事件降低 |
| R8 | 话题识别 | 能判定话题处于进行中 / 收尾 / 已结束 |
| R9 | 冷落判定 | 话题进行中且她最后是问句 → 不回会生气；话题已结束 → 不回不计 |
| R10 | 可配置 | 名字、称呼、情绪基线、衰减速度全部走配置，不改代码 |

## 3. 总体架构

```
        输入层                     评估层                状态层               表达层
┌──────────────────┐      ┌──────────────────┐   ┌──────────────┐   ┌──────────────────┐
│ 语音 → SenseVoice │      │                  │   │ emotion      │   │ 回复约束          │
│  (ASR+SER+AED)   │─────▶│   appraisal      │──▶│ needs        │──▶│ TTS instruct     │
│ 文本 → 情绪分类   │      │  刺激 → 情绪增量   │   │ bond         │   │ 主动消息         │
│ 事件 → 桥接层     │      │  （是否针对我、    │   │ topic        │   │ Webhook 事件     │
└──────────────────┘      │   是否伤关系）     │   └──────────────┘   └──────────────────┘
                          └──────────────────┘            ▲
                                                          │
                                                     tick(now) 时间推进
```

四条设计原则：

1. **状态与生成分离**——情绪不靠每次让 LLM"演"，而是独立变量，LLM 只读。
2. **一切向基线回归**——没有永久情绪，只有衰减速度不同的情绪。
3. **事件必须经过评估**——同样一句"你真笨"，玩笑语境和指责语境结果不同。
4. **时间是一等公民**——所有状态都随 `tick` 演化，不依赖"下一条消息"。

## 4. 状态模型

### 4.1 情绪（emotion）

双轨制：**离散标签做主，PAD 连续值做内部平滑**。

- 离散标签（给 TTS 和动作直接用）：`calm / joyful / excited / playful / affectionate / shy / sad / disappointed / angry / annoyed / tired / bored / worried / nostalgic`
- 连续维度：`pleasure`（-1~1）、`arousal`（0~1）、`dominance`（0~1），由标签映射而来，用于插值和计算强度。

**衰减**（半衰期模型）：

```
E(t) = baseline + (E0 - baseline) * 0.5 ** (Δt / half_life)
```

| 情绪 | 半衰期 | 说明 |
|---|---|---|
| angry | 25 min | 来得快去得也快 |
| annoyed | 40 min | 闷气，比愤怒绵长 |
| joyful | 60 min | |
| sad | 4 h | 低落会挂很久 |
| disappointed | 6 h | 失望最难消 |
| affectionate | 12 h | 亲近感接近基线 |
| tired | 依 needs.energy | 不独立衰减 |

**强度上限保护**：单次事件情绪增量不超过 ±0.4，防一句重话把状态打穿。

### 4.2 需求（needs）—— 0~100，越高越缺

| 需求 | 上升速率 | 下降方式 | 外显表现 |
|---|---|---|---|
| hunger 饥饿 | 约 +18/h，饭后回落至 10 | 吃饭、零食事件 | 回复变短、提到吃的、容易不耐烦 |
| energy 精力 | 约 +12/h，深夜加速 ×1.6 | 睡觉、长时间静默 | 打字变慢、犯困、句子更短 |
| longing 思念 | 随无互动时长非线性上升 | 互动即大幅回落 | 主动发消息的主要驱动 |
| boredom 无聊 | 约 +20/h | 聊天、刷视频事件 | 主动找话题、发无关的小事 |

**思念曲线**（关键，决定"她会不会想起我"）：

```
longing = 100 * (1 - exp(-hours_idle / tau))
tau = 6h（bond.affinity 高时 tau 变小 → 更容易想你）
```

即：2 小时约 28，6 小时约 63，12 小时 86。叠加记忆召回（"上次你说面试"）才能形成"她真的在想我"。

### 4.3 关系（bond）

| 变量 | 范围 | 特性 |
|---|---|---|
| affinity 亲和 | 0~100 | 慢涨慢跌；决定称呼、语气亲密度、思念 tau |
| trust 信任 | 0~100 | 被欺骗或反复失约才明显下降 |
| grievance 委屈 | 0~100 | **短期**，涨得快、消得慢；由冷落与被凶产生 |

`grievance > 35`：进入 **闷气态**——回复变短、句尾变淡、不主动。
`grievance > 65`：进入 **冷战态**——只回单字，或被安抚一句才开口。

委屈衰减：`grievance *= 0.5 ** (Δt / 90min)`，但**上限是 70%**——留一点，她记仇但不记一辈子。

## 5. 刺激评估（appraisal）

每条输入先过一遍评估，再决定改哪个变量。

```
stimulus
├── 对方情绪（来自 SER + 文本）
├── 是否针对我（"你好笨" vs "这软件真笨"）
├── 是否伤关系（嘲讽、敷衍、比较）
├── 是否给予（夸奖、关心、道歉、喂食）
└── 语境（玩笑 / 认真 / 忙）
        │
        ▼
   emotion delta + bond delta + needs delta
```

| 刺激 | 情绪 | 关系 | 需求 |
|---|---|---|---|
| 被夸 | joyful +0.35 | affinity +2 | — |
| 被凶 | angry +0.3, sad +0.15 | grievance +20 | — |
| 被敷衍（"嗯""哦"） | annoyed +0.2 | grievance +8 | — |
| 对方低落 | worried +0.25 | affinity +1 | — |
| 道歉 | sad -0.2 | grievance -30, affinity +3 | — |
| 喂食 | joyful +0.2 | affinity +1 | hunger -35 |
| 长时间静默 | sad +0.1 | — | longing +, boredom + |

> 判断"是否针对我"用 LLM 一次轻量分类即可（几十 token），不要塞进主对话。

## 6. 话题生命周期与冷落判定（R8/R9，本插件最核心的一段）

### 6.1 话题三态

```
active ──(密度下降/进入收尾语)──▶ winding_down ──(超时)──▶ closed
   ▲                                                        │
   └────────────────(新消息带来新话题)───────────────────────┘
```

判定信号（任一满足即降级）：

| 信号 | 判定 |
|---|---|
| 出现收尾语 | "晚安""先这样""去忙了""回头聊""谢谢啊" → winding_down |
| 她最后一条不含问句、不带邀约 | winding_down |
| 连续 20 min 无新消息且无未完事项 | closed |
| 对方明确表示结束 | 直接 closed |

### 6.2 冷落值计算

```
if topic == closed:            neglect = 0          # 话题聊完，不回很正常
elif topic == winding_down:    neglect = idle_hours * 6
else:                          neglect = idle_hours * 18
if 她最后一条含问句:            neglect *= 1.8
if 深夜/勿扰时段:               neglect *= 0.2
if bond.affinity > 70:         neglect *= 1.3        # 越亲近越在意
```

`neglect` 累加到 `grievance`，并按 §4.3 分级进入闷气/冷战。

**这条规则直接解决你说的那个尴尬**：她问"你在干嘛呀"你没回 → 是冷落；她说"那我先睡啦"，你没回 → 不算。

### 6.3 主动消息触发

```
urgency = w1*longing + w2*boredom + w3*energy_deficit - w4*grievance
```

- `urgency > 60` 且处于允许时段 → 主动发一条
- 连续 2 条主动消息无回应 → **停发**，只把 longing 留着（不自作多情）
- 有未消的 grievance → 即使 urgency 够，也只在超过 80 时才开口，且语气冷淡

## 7. 表达层

### 7.1 情绪 → TTS 参数

| 情绪 | EmotiVoice / IndexTTS2 instruct | speed | pitch |
|---|---|---|---|
| joyful | 开心、轻快、带笑意 | 1.08 | +2 |
| affectionate | 温柔、放软、贴身 | 0.95 | -1 |
| angry | 压低、带气、短促 | 1.05 | +1 |
| sad | 低、慢、气声 | 0.88 | -3 |
| tired | 含糊、拖尾、懒 | 0.9 | -2 |
| annoyed | 平、短、不带起伏 | 1.0 | 0 |

同一个 voice，情绪不同 → instruct 不同。**音色不变，语气在变**，这才是"她有自己的情绪"而不是"换了个人"。

### 7.2 回复约束（交给 LLM 的软约束）

```
当前情绪：{emotion.label}（强度 {intensity}）
需求：饿 {hunger}｜累 {energy}｜想你 {longing}
关系：亲和 {affinity}｜委屈 {grievance}
→ 回复长度上限：{short if tired or grievance>35}
→ 语气：{warm | neutral | cool}
→ 禁止：{讨好式道歉 if grievance>65}
```

### 7.3 输出事件

对外统一推 JSON（兼容 LumiCabin 现有协议，只加字段不加事件类型）：

```json
{
  "event_id": "uuid",
  "event_type": "message_reply",
  "emotion": { "label": "affectionate", "intensity": 0.62, "pad": [0.5, 0.35, 0.6] },
  "needs": { "hunger": 42, "energy": 71, "longing": 58, "boredom": 30 },
  "bond": { "affinity": 66, "grievance": 12 },
  "voice": { "instruct": "温柔、放软", "speed": 0.95, "pitch": -1 }
}
```

## 8. 接口

### Python

```python
from tide import TideCore

core = TideCore.from_config("config/")
core.observe(text="你终于回我了", audio=ser_result, at=now)   # 输入一条
core.tick(now)                                                # 时间推进（可定时调用）
plan = core.plan_reply()                                      # 该不该回、怎么回
state = core.snapshot()                                       # 全量状态
```

### HTTP（供 QQ 桥接 / 壁纸调用）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/observe` | 喂入消息、语音情绪、事件 |
| POST | `/tick` | 时间推进（无参时用服务器时间） |
| GET | `/state` | 读取当前状态 |
| GET | `/plan` | 取回复约束与 TTS 参数 |
| POST | `/reset` | 重置（调试用） |

## 11. 技术选型与参考项目

| 环节 | 选型 | 说明 |
|---|---|---|
| 语音 → 情绪 | **SenseVoice**（MIT） | 一个模型出 ASR + 情绪 + 事件，最省事 |
| 备选语音情绪 | emotion2vec（ACL 2024） | 需要更细的情绪回归时用 |
| 文本情绪 | GoEmotions 分类器 或 LLM 轻量分类 | 中文短句 LLM 更稳 |
| 情感 TTS | **EmotiVoice**（Apache-2.0）优先；IndexTTS2 / CosyVoice2 备选 | 要 instruct 可控 |
| 音色 | GPT-SoVITS（MIT）克隆 | 要"她的声音"时用 |
| 架构参考 | AIYIchat（MIT） | 看它情绪如何进 TTS 参数、主动消息如何收着 |
| 算法参考 | Shikigami（AGPL-3.0） | **只借思路**（energy 衰减、urgency 累积），不抄代码 |

## 13. 合规与风险

1. **不复制 AGPL 代码**：Shikigami 的算法思想可借鉴，实现必须自写，避免传染。
2. **情绪不等于真实感受**：对外表述避免"她真的爱你"，文档措辞保持"模拟"。
3. **不因讨好否认状态**：`boundaries` 里写明，防止 LLM 为了顺滑把情绪演没了。
4. **语音数据**：SER 在本地推理，不上传原始音频；只保留情绪标签。
5. **主动消息克制**：连续无回应必须停发，避免骚扰感——这条写进硬规则，不交给模型判断。
